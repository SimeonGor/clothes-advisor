# Архитектурное ревью ЛР4

При разборе проследили три операции от входа до commit — выдачу доступа, фоновый подбор и доставку уведомления. Затем проверили границы доступа к файлам и поведение при повторной доставке.

| Граница | Что проверили |
| --- | --- |
| Gateway и сервисы | Браузер получает задания и уведомления по JWT. Внутренние операции чтения файла и проверки снимка используют отдельные служебные учётные данные. В Compose порты бизнес-сервисов, PostgreSQL и Kafka доступны внутри сети. |
| Account | Изменение разрешения и запись события входят в один SQL-запрос. Повторная выдача ранее выданного доступа не порождает новое уведомление. |
| Wardrobe | Проверка аккаунта выполняется до локальной транзакции применения результата. Блокировки вещей и фото, создание ресурса, конечный статус задания и исходящее подтверждение входят в одну транзакцию. |
| Recommendation | Вызов провайдера проходит вне транзакции. Состояние слота переживает рестарт. Если поток прервался после отправки запроса, оператор разбирает исход перед возобновлением работы. |
| File | У сервиса собственные метаданные и закрытый объектный ключ. Принадлежность вещи и пользовательские разрешения проверяет wardrobe. |
| Notification | Обработчик фиксирует событие для определённого получателя. Уникальность пары получатель/событие защищает от повторной доставки. HTTP-проверка сверяет текущий статус пользователя. |

### Что исправили

Обработчики команд и подтверждений в recommendation содержали SQL и правила повторного применения. Перенесли работу с сохранённым запросом в `RecommendationRequestStore`. Повтор терминального результата восстанавливает исходящее событие под той же блокировкой периода, что и приём команды.

Сценарий применения результата в wardrobe принимал Kafka `ConsumerRecord`. Теперь listener разбирает транспортное сообщение, сценарий работает с событием, а `AiJobRepository` выполняет запросы и блокировки. Тест с ошибкой записи исходящего события проверяет откат и последующую повторную доставку.

### Что важно при эксплуатации

ACK брокера подтверждает запись в Kafka. Применение результата в wardrobe подтверждает отдельное событие `AiJobFinalized`. При разборе зависшего задания нужно проверить обе точки. Для рекомендаций, которые провайдер мог принять до обрыва связи, автоматический повтор опасен расходованием личной квоты.
