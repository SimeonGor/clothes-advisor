# Clothes Advisor

REST-сервис для подбора одежды из личного гардероба с учётом погоды. Учебный проект по [курсу высоконагруженных систем](https://github.com/Discipliny/highload_systems).

- **USER** загружает вещи и фотографии, составляет образы вручную или через AI.
- **STYLIST** с разрешения владельца просматривает гардероб, создаёт образы и оценивает чужие.
- **ADMIN** управляет ролями и блокировками, просматривает и удаляет фотографии и образы.

Стек: Kotlin, Spring Boot, PostgreSQL, Spring Data JDBC, Flyway, Yandex Object Storage и OpenAI. Приложение — монолит; пакеты разделены по техническим слоям, внутри — по предметным областям.

В этой версии нет входа и контроля доступа к API. Действующий пользователь задаётся заголовком `X-User-Id`; это не аутентификация. Приложение предназначено только для доверенного локального окружения. Проверки владельца, разрешений стилиста и другие бизнес-правила сохраняются.

## Быстрый запуск

Нужны Docker с Compose и приватный бакет Yandex Object Storage с доступом на чтение и загрузку файлов.

Если `.env` ещё нет, создайте его из примера:

```shell
cp .env.example .env
```

Заполните в `.env`:

- `S3_BUCKET` — имя приватного бакета.
- `YANDEX_IAM_TOKEN` — действующий IAM-токен сервисного аккаунта с правами чтения и загрузки объектов в этот бакет.
- `DB_PASSWORD` — пароль PostgreSQL; значение из примера подходит только для локального запуска.
- `APP_UID` — результат `id -u`; `CHATGPT_CREDENTIALS_DIR` и `OPENAI_MODEL` — настройки [подключения ChatGPT](#ai-подбор).

Профиль `local` уже включён в примере. Он создаёт аккаунты `user`, `stylist`, `admin`; повторный запуск не меняет существующие аккаунты. Регистрации через API нет.

```shell
docker compose up --build -d
```

После старта приложения проверьте `curl http://127.0.0.1:8080/actuator/health`: ожидаемый ответ — `{"status":"UP"}`. Порты приложения и БД доступны только с локального компьютера; их можно изменить через `APP_PORT` и `DB_PORT`. Ссылки ниже рассчитаны на порт 8080.

Остановка — `docker compose down`. Данные PostgreSQL сохраняются в именованном томе. `.env` с паролями и ключами не коммитится.

Миграции не исправляют старые данные автоматически. Если в существующей БД есть названия длиннее 300 символов или логины, цвет и материал длиннее 100, новые ограничения остановят запуск: такие записи нужно сначала проверить и исправить вручную.

Фотографии передаются в [HTTP API Yandex Object Storage](https://yandex.cloud/ru/docs/storage/api-ref/authentication) с IAM-токеном, без AWS SDK. После истечения токена обновите `YANDEX_IAM_TOKEN` в `.env` и выполните `docker compose up -d --force-recreate app`. Автоматического обновления токена нет.

## Демонстрационный интерфейс

Откройте [Clothes Advisor](http://127.0.0.1:8080/) и выберите тестового пользователя. Здесь можно управлять вещами и фотографиями, создавать образы вручную или через AI. Интерфейс включён в JAR и запускается тем же Docker Compose, отдельная сборка фронтенда не нужна.

Выбор пользователя хранится только в памяти вкладки. При переключении данные предыдущего пользователя очищаются. Сценарии стилиста и администратора доступны через REST API; AI-подбор — аккаунту `user` при настроенном подключении ChatGPT.

## API

Сначала получите ID тестового пользователя:

```shell
curl http://127.0.0.1:8080/api/admin/users
```

Затем передавайте его в запросах, где нужен действующий пользователь:

```shell
curl http://127.0.0.1:8080/api/wardrobe/items -H 'X-User-Id: 1'
curl http://127.0.0.1:8080/api/wardrobe/items \
  -H 'X-User-Id: 1' -H 'Content-Type: application/json' \
  -d '{"name":"Рубашка","categoryId":1,"color":"Белый","material":"Хлопок"}'
```

Замените `1` фактическим ID из списка. Локальная документация доступна в [Swagger UI](http://127.0.0.1:8080/swagger-ui/index.html), [OpenAPI JSON](http://127.0.0.1:8080/v3/api-docs) и [OpenAPI YAML](http://127.0.0.1:8080/v3/api-docs.yaml). Маршруты и бизнес-правила описаны в [требованиях](docs/requirements.md). Заголовок `X-User-Id` показывается в Swagger только для методов, которым нужен действующий пользователь; глобальной схемы Bearer нет.

## AI-подбор

Локальная интеграция использует личную подписку ChatGPT и доступна аккаунту `user`. API-ключ и автоматический переход на платный API не используются. В настройках ChatGPT Usage отключите дополнительные кредиты для подключения.

Вход выполняется отдельной локальной утилитой, которая не входит в этот репозиторий. Приложению нужны созданные ею `registration.json` и `credentials.json`:

- `CHATGPT_CREDENTIALS_DIR` — абсолютный путь к каталогу этих файлов вне репозитория. Процессу приложения нужен доступ на чтение файлов через ОС; рекомендуется ограничить доступ к credentials своей учётной записью.
- `OPENAI_MODEL` — доступная аккаунту модель с поддержкой изображений и структурированного ответа.

Подключение уже включено в `compose.yaml`; команда запуска та же: `docker compose up --build -d`. Каталог должен существовать до запуска: он монтируется в `/run/chatgpt` только для чтения. Контейнер работает без root, с UID владельца файлов из `APP_UID`.

Если нужен отдельный PKCS12 для OpenAI, положите его в тот же каталог и задайте `CHATGPT_TRUST_STORE=/run/chatgpt/<имя файла>`; пароль хранилища — `changeit`. Иначе оставьте переменную пустой. Это доверие применяется только к клиенту OpenAI.

Без действующего подключения AI возвращает 503; остальные функции работают. Для запуска без AI можно указать пустой каталог и оставить `OPENAI_MODEL` пустым. После истечения токена нужен повторный вход через утилиту, перезапуск контейнера не требуется. OAuth-токены не храните в `.env` или Git.

## Сборка и тесты

Для сборки нужен JDK 25, для интеграционных тестов — работающий Docker. Gradle запускается через wrapper:

```shell
./gradlew bootJar           # JAR в build/libs/
./gradlew test              # unit-тесты и интеграционные тесты с PostgreSQL
./gradlew check             # тесты и проверка покрытия строк ≥70%
./gradlew jacocoTestReport  # отчёт без проверки порога
```

Отчёты JaCoCo: `build/reports/jacoco/test/html/index.html` и `build/reports/jacoco/test/jacocoTestReport.xml`. Классы приложения из покрытия не исключаются. Unit-тесты сервисов используют Mockito без Spring и БД. Интеграционные тесты работают с PostgreSQL Testcontainers, готовят и проверяют данные через JDBC, очищают их после теста. HTTP-клиенты проверяются на локальных заглушках; секреты из `.env` и реальные вызовы S3/OpenAI не нужны.

Для Colima на macOS перед тестами:

```shell
export DOCKER_HOST="unix://${HOME}/.colima/default/docker.sock"
export TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE=/var/run/docker.sock
export TESTCONTAINERS_HOST_OVERRIDE=127.0.0.1
```

## Ограничения

- Погода задаётся вручную; погодного сервиса нет.
- Образы неизменяемы. Вещь из сохранённого образа удалить нельзя.
- Удаление фотографии убирает запись БД, но не файл S3. Автоочистки нет; при сбое загрузки могут остаться файлы без метаданных.
- При AI-подборе фотографии передаются OpenAI. Бакет остаётся приватным.
- Публикация в интернет не входит в ЛР1: прежде нужно вернуть аутентификацию и контроль доступа, настроить HTTPS и отдельно согласовать использование подключения ChatGPT.
